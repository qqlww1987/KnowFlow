# 公路桥梁施工工艺知识图谱（Neo4j）技术白皮书

> **版本**：V2.0  
> **适用图库**：`neo4j`（公路桥梁施工工艺知识库）  
> **构建目标**：施工方案自动生成、工序依赖推理、设备-材料-构件供应链分析、进度计划纠偏、经济效益分析、方案比选推理、地质条件适配  
> **最后更新**：2026-05-14

---

## 一、图库架构总览

本图库采用 **"工艺-工序-资源-规范"四层模型**，以施工工艺流程图为骨架，串联设备、材料、构件、质控点、规范标准六类共享实体，并新增**工法上层节点（WorkMethod）、项目节点（Project）、地质条件节点（GeoCondition）、工艺参数节点（ProcessParameter）**四类扩展实体，形成"**共享实体层 + 工艺专属层 + 工法元信息层 + 工程上下文层**"四层架构，支撑自然语言查询与智能推理。

### 1.1 节点标签清单（Node Labels）

| 标签 | 数量级 | 业务含义 | 典型属性 | 所属层级 |
|:---|:---:|:---|:---|:---|
| `Step` | 核心 | 施工工序节点 | `step_id`, `name`, `type`, `technical_params`, `pre_conditions` | 工艺专属层 |
| `Process` | 少量 | 工艺总览/主流程 | `process_id`, `process_name`, `figure_ref`, `process_type` | 工艺专属层 |
| `Equipment` | 中 | 施工机械设备 | `equipment_id`, `name`, `category`, `embedding_text` | 共享实体层 |
| `Material` | 中 | 工程材料 | `material_id`, `name`, `model`, `usage_location`, `embedding_text` | 共享实体层 |
| `Component` | 中 | 构件/部件 | `component_id`, `name`, `category`, `nature`, `embedding_text` | 共享实体层 |
| `QualityCheck` | 中 | 质控点/检验项 | `qc_id`, `name`, `check_item`, `standard_requirement` | 工艺专属层 |
| `Standard` | 少 | 规范标准/法规 | `standard_id`, `code`, `name`, `category`, `status`, `publish_date`, `superseded_by` | 共享实体层 |
| `Decision` | 少 | 决策条件/分支 | `decision_id`, `condition`, `branch_true`, `branch_false` | 工艺专属层 |
| `Cycle` | 少 | 循环定义节点 | `cycle_id`, `from_step`, `to_step`, `description` | 工艺专属层 |
| `Method` | 少 | 工法/技术方法（细分技术） | `method_id`, `name`, `applicable_scope` | 工艺专属层 |
| `**WorkMethod**` | **少** | **工法上层节点（承载元信息）** | `method_id`, `method_name`, `method_level`, `completion_unit`, `economic_benefit_saving`, `embedding_text` | **工法元信息层（新增V2.0）** |
| `**Project**` | **少** | **应用实例/工程项目** | `project_id`, `project_name`, `location`, `geology_summary`, `total_cost`, `application_effect` | **工程上下文层（新增V2.0）** |
| `**GeoCondition**` | **少** | **地质/环境条件** | `geo_id`, `name`, `features`, `soil_type`, `water_table`, `risk_level` | **工程上下文层（新增V2.0）** |
| `**ProcessParameter**` | **中** | **工艺参数（独立节点化）** | `param_id`, `name`, `value`, `unit`, `constraint_type`, `threshold`, `alert_level` | **工艺专属层（新增V2.0）** |

> **说明**：`Method` 与 `WorkMethod` 的区别——`Method` 记录具体技术方法（如"压密注浆法"），`WorkMethod` 承载整个工法的元信息（级别、完成单位、经济效益等）。一个 WorkMethod 可包含多个 Method。

## 二、核心数据模型详解

### 2.1 工序节点（Step）

**标签**：`:Step`  
**定位**：图库骨架节点，每个方框对应一个工序。

**属性规范**：

| 属性名 | 类型 | 必填 | 说明 |
|:---|:---|:---:|:---|
| `step_id` | String | ✅ | 全局唯一ID，格式 `S{序号}`，如 `S1`, `S7` |
| `name` | String | ✅ | 工序名称，与原文档保持一致 |
| `type` | String | ✅ | 枚举：`start`（起点）、`operation`（操作）、`transport`（位移）、`control`（控制） |
| `description` | String | 建议 | 详细操作描述 |
| `technical_params` | String | 建议 | 关键技术参数（尺寸、强度、温度等）。**V2.0提示**：此字段中抽取的关键数值参数应同步创建为 ProcessParameter 独立节点 |
| `pre_conditions` | String[] | 可选 | 前置条件文本列表 |
| `has_internal_cycle` | Boolean | 可选 | 是否含内部循环 |
| `cycle_description` | String | 可选 | 循环逻辑说明 |

**入度校验规则**：
- **流程起点 / 独立汇入点**：入度 = 0
- **中间节点**：入度 = 1（单线）或 >1（多源汇入）
- **循环返回点**：入度 = 正常NEXT + CYCLE_NEXT

## 三、拓扑关系建模规范

### 3.1 NEXT 关系（核心顺序）

```cypher
(a:Step)-[:NEXT {relation_type: '主工序顺序'}]->(b:Step)
(a:Step)-[:NEXT {relation_type: '汇入'}]->(b:Step)
```

**规则**：
1. **主竖线**上相邻工序建立 `relation_type: '主工序顺序'`
2. **左侧/右侧汇入**方框建立 `relation_type: '汇入'`，汇入点入度必须为 0
3. **严禁**将汇入方框的 next 指向主竖线上游工序

### 3.2 CYCLE_NEXT 关系（循环作业）

```cypher
(s:Step)-[:CYCLE_NEXT {relation_type: '内部循环', description: '...'}]->(s)
```

**适用场景**：分层开挖、挂篮循环行走、节段循环浇筑。

### 3.3 资源关联关系

| 关系 | 建模原则 | 属性（V2.0） |
|:---|:---|:---|
| `USES_EQUIPMENT` | 某工序明确使用的机械/仪器 | **`quantity`**: 数量（如"1台"、"2套"）；**`usage`**: 用途说明 |
| `USES_MATERIAL` / `CONSUMES_MATERIAL` | 工序消耗或安装的材料 | **`quantity`**: 数量（如"按设计"、"分层计算"）；**`usage`**: 使用部位 |
| `OPERATES_COMPONENT` / `HAS_COMPONENT` | 工序操作或涉及的构件 | — |
| `HAS_QUALITY_CHECK` | 每道工序至少关联一个质控点 | — |
| `FOLLOWS_STANDARD` | 工序执行所依据的规范 | — |

### 3.4 工法元信息关系（V2.0 新增）

| 关系 | 方向 | 建模原则 | 属性 |
|:---|:---|:---|:---|
| `CONTAINS_PROCESS` | WorkMethod → Process | 一个工法包含一个主工艺 | — |
| `APPLIED_IN` | WorkMethod → Project | 工法在哪些项目中应用验证 | `effect`: 应用效果 |
| `SUITABLE_FOR` | WorkMethod → GeoCondition | 工法适用的地质条件 | `match_degree`: 匹配度；`confidence`: 置信度 |
| `HAS_PARAMETER` | Process → ProcessParameter | 工艺包含的全部参数 | — |
| `STEP_HAS_PARAMETER` | Step → ProcessParameter | 参数与具体工序的关联 | — |
| `COMPARES_TO` | WorkMethod → WorkMethod | 与替代工法的对比 | `this_advantage`, `alternative_advantage`, `comparison_dimension` |
| `MATCHES_GEOLOGY` | GeoCondition → Project | 项目的地质条件匹配 | — |

## 四、核心查询手册（可直接复制使用）

### 4.1 查询完整主流程拓扑

```cypher
// 查看某工艺的全部工序及紧后关系
MATCH (p:Process {process_id: 'PROCESS_CHENGTAISHENSHUI_001'})-[:CONTAINS_STEP]->(s:Step)
OPTIONAL MATCH (s)-[:NEXT]->(next:Step)
OPTIONAL MATCH (prev:Step)-[:NEXT]->(s)
WITH s, 
     collect(DISTINCT prev.name) AS 前置工序列表,
     collect(DISTINCT next.name) AS 紧后工序列表
RETURN s.step_id AS 工序ID, 
       s.name AS 工序名称, 
       s.type AS 类型,
       前置工序列表 AS 前置工序,
       紧后工序列表 AS 紧后工序
ORDER BY s.step_id
```

### 4.2 查询紧前工序与紧后工序

```cypher
// 查询指定工序的紧前和紧后
MATCH (prev:Step)-[:NEXT]->(s:Step {name: '运梁机就位'})-[:NEXT]->(next:Step)
RETURN prev.name AS 紧前工序, s.name AS 当前工序, next.name AS 紧后工序

// 模糊查询（like 语义）
MATCH (prev:Step)-[:NEXT]->(s:Step)-[:NEXT]->(next:Step)
WHERE s.name CONTAINS '挂篮行走'
RETURN prev.name AS 紧前工序, s.name AS 当前工序, next.name AS 紧后工序
```

### 4.3 查询循环工序

### 4.4 延期影响分析（关键路径推理）


## 六、数据入库规范

### 6.1 ID 命名规范

| 实体类型 | ID 格式 | 示例 | 层级 |
|:---|:---|:---|:---|
| 工序 | `S{序号}` | `S1`, `S14` | 工艺专属 |
| 工艺 | `PROCESS_{缩写}_{序号}` | `PROCESS_CHENGTAISHENSHUI_001` | 工艺专属 |
| 设备 | `E{序号}` | `E1` | 共享实体 |
| 材料 | `M{序号}` | `M14` | 共享实体 |
| 构件 | `C{序号}` | `C6` | 共享实体 |
| 质控点 | `Q{序号}` | `Q18` | 工艺专属 |
| 规范 | `ST{序号}` | `ST3` | 共享实体 |
| **工法** | **`WM_{专业}_{级别}_{序号}`** | **`WM_QL_05_SJ_C3_2025`** | **工法元信息（V2.0）** |
| **项目** | **`PRJ_{缩写}_{序号}`** | **`PRJ_CHENGTAISHENSHUI_001`** | **工程上下文（V2.0）** |
| **地质条件** | **`GEO_{缩写}_{序号}`** | **`GEO_CHENGTAISHENSHUI_001`** | **工程上下文（V2.0）** |
| **工艺参数** | **`PP_{三位序号}`** | **`PP_001`** | **工艺专属（V2.0）** |

### 6.2 属性填写规范

- **字符串数组**（如 `pre_conditions`）使用 JSON 数组格式存入节点属性
- **空值处理**：无值属性建议不创建或存空字符串，避免 `"null"` 字符串
- **数值单位**：技术参数中必须带单位，如 `分层厚度≤30cm`，`温差≤25℃`
- **图号保留**：所有 Process 必须关联 `figure_ref`，确保可追溯原文
- **embedding_text（V2.0）**：所有共享实体节点建议填写，格式为 `实体名称 功能/规格 适用场景`，用于RAG语义检索
- **Standard 版本管理（V2.0）**：`status` 必须填写，`superseded_by` 如规范现行则为 `""`（空字符串），不可省略

### 6.3 防重复策略

入库前执行以下检测：

```cypher
// 检查是否已存在同 ID 节点
MATCH (s:Step {step_id: 'S7'})
RETURN count(s) > 0 AS 已存在

// 或：按工艺整体检测
MATCH (p:Process {process_id: 'PROCESS_CHENGTAISHENSHUI_001'})
RETURN count(p) > 0 AS 已存在
```

若已存在，先执行 **"先删后建"** 脚本（见本文档配套 Cypher 文件），再重新导入。

**共享实体防冲突检测（V2.0）**：

```cypher
// 检测 Equipment 属性冲突（同ID不同属性）
MATCH (e:Equipment {equipment_id: 'E1'})
WHERE e.name <> '75T履带吊'
RETURN e.equipment_id AS 冲突ID, e.name AS 实际名称, '75T履带吊' AS 期望名称
```

## 八、附录：常见问题排查

| 问题 | 原因 | 解决 |
|:---|:---|:---|
| `WITH is required between CREATE and MATCH` | 同一语句内先 CREATE 后 MATCH | 拆分为独立语句，或用 `UNWIND + MATCH + CREATE` 批量模式 |
| 节点重复 | 多次导入未清理旧数据 | 执行 `DETACH DELETE` 清理后再导入 |
| 关系方向错误 | NEXT 指向反了 | 严格按流程图箭头方向，主竖线自上而下 |
| 汇入点入度不为 0 | 错误建立了汇入点到上游的关系 | 删除错误关系，汇入点只保留指向汇入目标的关系 |
| 查询结果为空 | 属性值含隐藏字符或空格 | 使用 `CONTAINS` 替代 `=` 进行模糊匹配 |
| **规范废止未检出（V2.0）** | **Standard.superseded_by 为空字符串而非缺失** | **查询条件用 `st.superseded_by <> ''` 而非 `st.superseded_by IS NOT NULL`** |
| **参数告警未触发（V2.0）** | **ProcessParameter 未从 technical_params 中抽取** | **入库前增加参数抽取步骤，见配套抽取提示词** |
| **工法推荐无结果（V2.0）** | **WorkMethod 与 GeoCondition 未建立 SUITABLE_FOR 关系** | **确保入库脚本包含地质条件匹配关系** |
